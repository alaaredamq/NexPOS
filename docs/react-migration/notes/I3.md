## Endpoints
`GET audit-logs` (page/pageSize, `dir` = `desc` default / `asc`, `q`, `from`, `to`, `userId`, `username`, `category`, `outcome`, `minSeverity`, `entityType`, `entityId`, `action`, `correlationId`) · `GET audit-logs/summary` (the four tiles) · `GET audit-logs/options` (user / record type / action drop-downs) · `GET audit-logs/{id}` (entry + field changes + extra JSON + request group size) · `GET audit-logs/export` (CSV, same filters, streamed).
Permission for all five: `AuditLogs.Read` (copied from the Razor controller). Nothing but GET exists; POST/PUT/DELETE answer 405 (tested).

## Decisions / differences from the Razor page
1. **Details are a drawer, not a Bootstrap modal**, and its state is the URL (`?entry=<id>`): a link to an entry works, Escape / back closes it. Same content and the same drill-down buttons (this request, history of this record, everything by this user, copy request id). A drill-down starts from a clean slate (it replaces the filters, as before) and closes the drawer.
2. **Unknown filter values are a 400 `validation_failed`**, with the field in `errors`. The Razor controller silently ignored a bad `category=` and showed the unfiltered log. `sort` other than `time` is also a 400 (time is the only order there is; `dir` flips it).
3. **No Apply button.** Filters apply as chosen; free text and the record number wait for the typing to stop / Enter. The Razor "Refresh" stays (it refetches the list and the tiles).
4. **All state is in the URL** (`?category=Security&type=Product&record=42&request=…&dir=asc`), so a refresh, the back button and a link from support land on the same rows. The old `?correlationId=&entityType=&entityId=&userId=&search=` addresses are *not* read by the SPA (new names: `request`, `type`, `record`, `user`, `q`). Nothing in the codebase links to them; I grepped views and scripts.
5. **Time filter** uses the browser's local `datetime-local` and is sent as UTC instants; "to 14:30" includes the whole of minute 14:30 (as before). The "Last hour / Today / 7 / 30 days / All time" chips set `from` once (they are shortcuts, not a persistent mode, so none shows as selected).
6. **The Time column is the only sortable one** and a click flips newest/oldest first (the table's usual asc → desc → off cycle would make the default state take two clicks to leave).
7. **Page sizes are 25/50/100/200** (the Razor length menu); default 50. From 100 rows up the table is windowed (fixed 58 px rows, description on one line with the full text as tooltip and in the drawer), so a 200-row page stays light. The server clamps `take` to 500 and the API's `pageSize` max is 200.
8. **The Razor view's "Tbl_*" DataTables strings** are unused now (the shared table / pagination have their own); the keys stay in the namespace because the export script keeps them.
9. Export is a GET (the Razor one was too). It is still itself audited (`AuditExported`, with the row count and filter).
10. Descriptions and record labels are shown as the data was typed (`dir="auto"`); ids, paths, IPs, versions and times are forced LTR inside Arabic text.

## Watch list (pre-existing, not changed here)
- **The log is large and noisy by design:** every API request writes a `Request` row, so the table fills quickly (a demo session wrote 80 rows in a minute). A default "hide Request rows" toggle would be a feature, so it is on the later list.
- `GetFilterOptionsAsync` is cached for 60 s server-side, and the client keeps it 60 s too: a brand-new user or action may take up to two minutes to appear in the drop-downs.
- The user drop-down lists every actor that ever appears, including names typed into failed sign-ins (found by `username`, not id), as before.
- Entries are append-only; the optional retention purge (audited) is the only thing that removes rows and is outside this module.
- Export cap is 100,000 rows (`IAuditLogService.ExportMaxRows`). Once the first bytes are streamed a failure can only cut the file short; there is no way to report it in-band.

## Not done / not verified
- **Full Vitest at default parallelism fails** (16 failures in other tracks' tests, 10 on a clean `react/main` checkout): first-render `findBy…` calls hit their 1 s timeout while many workers compete for CPU. All pass with `--maxWorkers=2`. Not touched here; worth raising `asyncUtilTimeout` in the shared test setup (that is a frozen file, so Z or a one-line core PR).
- Licence-stopped and idle-timeout behaviour are inherited from the shell: the audit page is a read-only view, not a sales route, so a stopped licence leaves it open (as the Razor page was).
- Audit rows: the requests themselves are audited by `AuditRequestMiddleware` as `GET Api.AuditLogs/...`; the explicit `AuditExported` event is kept. Opening the viewer is not audited as an event of its own (it was not before either) - though each viewer request is a `Request` row, so looking at the log adds rows to the log.
- A light-weight RTL check of the drawer was done at 1366 only; the drawer is `min(720px, 100%)` wide, so on a 900 px tablet it is a full-height panel over the list.
