# 0F — Serving, build and Electron: handoff notes

**Branch:** `react/0F`. **Status:** ◑ in review.

## What changed
- `Web/Program.cs`
  - Static-file cache rules: `/app/assets/*` (Vite content-hashed) → `public,max-age=31536000,immutable`; everything else under `/app/`
    (index.html) → `no-cache` so an update is picked up on next load. Other buckets unchanged.
  - `app.MapFallbackToFile("/app/{*path:nonfile}", "app/index.html")` after the MVC routes. `nonfile` keeps missing assets as real 404s;
    `/api`, `/swagger` and MVC URLs are outside `/app`, so nothing there is swallowed.
- `Web/Web.csproj`
  - `BuildClient` target (Release only, `client/package.json` present, not `-p:SkipClientBuild=true`): `npm ci` if `client/node_modules` is missing, then `npm run build`.
    (Plan said "npm ci && npm run build"; skipping `npm ci` when deps exist keeps repeat Release builds fast.)
  - `PublishClientOutput` target adds `wwwroot/app/**` to the publish list explicitly, because wwwroot is globbed at evaluation time — on a clean checkout
    the SPA would not exist yet and would silently be left out of the publish. Verified with a clean-checkout `dotnet publish -c Release`.
- `build-electron.ps1`: Step 0 builds the client (`npm ci`, `npm run build` incl. bundle budget), publish gets `-p:SkipClientBuild=true`,
  and the script fails if `publish\app\wwwroot\app\index.html` is missing.
- `electron-main.js`: two env overrides, both defaulting to old behaviour — `NEXPOS_START_PATH` (default `/`; `/app` opens the SPA) and
  `NEXPOS_APP_URL` (default `http://localhost:5000`; for test runs against an isolated server). **No change to zoom**: it is still applied by the main
  process on `did-finish-load` (1500 CSS px / 0.8 min) and Ctrl +/-/0, so the SPA needs no zoom API. At Cutover leave `START_PATH` alone — the server's home redirect goes to `/app`.
- `client/src/core/electron.ts` (+ test): typed `electron.isElectron | listPrinters() | printSticker()` over `window.nexpos`, with browser no-op fallbacks.
  These are the only native APIs in `electron-preload.js`. Receipt printing (`nexprint.js`) is a plain `fetch` POST to server print endpoints → SPA uses `fetch`, no bridge.
- `BUILD_NEW_INSTALLER.md`: addendum on the client build.

## Verified (isolated demo DB on :5055, never `nexpos.db`)
- Clean checkout `dotnet publish -c Release` runs the client build and the publish folder contains `wwwroot/app/{index.html,assets/*}`.
- `/app`, `/app/`, `/app/deep/link`, `/app/index.html` → 200 index.html; `/app/assets/missing.js`, `/app/foo.png` → 404; `/en/Account/Login` unaffected.
- Cache headers with a session cookie: assets immutable, index/deep link `no-cache`.
- Real Electron (Playwright `_electron`) with `NEXPOS_START_PATH=/app`: loads `/app`, SPA renders, `window.nexpos` has `isElectron/listPrinters/printSticker`, reload and a deep link both work, zoom factor kept.
- `npm run dev` on :5173 serves `/app/` and proxies `/api` to :5000.
- `npm run lint`, `npm test` (4 passing), `npm run build` (96 KB gzip entry).

## Not verified
- A full `.\build-electron.ps1 win-installer` run (self-contained ReadyToRun publish + electron-builder, several minutes). Script syntax parses; the pieces were run separately.
- Electron zoom on a small screen: the test machine's screen is wide, so zoom stayed 1.0; the zoom code is untouched.

## Watch
- **curl without a cookie jar shows `Cache-Control: no-cache,no-store` on every response**, including old `/css/*`. That is ASP.NET's session middleware marking a *new* session; real clients (which keep the cookie) get the intended headers. Test caching with `curl -b/-c`.
- `LanguageMiddleware` runs for `/app/*` too and sets the culture cookie/session — harmless, but 0A's `Accept-Language` work for `/api/*` should keep that in mind.
- Visual Studio's debugger locks `Web\bin`; building from this worktree avoids that.
- Electron needs `ELECTRON_RUN_AS_NODE` unset to run from inside the Claude/VS Code terminal (it is set there).
