# Fixes after hands-on use (2026-11-01)

Branch `react/fixes` (off `react/main` at the P4 merge). Reported while using the app; each item below says what was wrong and what changed.

| # | Report | Cause | Fix |
|---|--------|-------|-----|
| 1 | Switch the till to Arabic, go to the dashboard: English | The old Razor pages keep the language in the URL (`/ar/...`) and an HttpOnly cookie; the SPA keeps it in `localStorage`. Nothing connected them, so leaving a Razor page for a migrated page (or back) lost the language. | A readable cookie `nexpos.lang` is the shared choice. `LanguageMiddleware` writes it for pages whose language is in the URL (never for `/app/...` or `/api/...`, which carry no choice). The SPA writes it on every change (`writeStoredLanguage`) and reads it once at start (`syncLanguageFromCookie`, called before i18n initialises). |
| 2 | Backup, Settings, License "still not moved" | The nav already linked them to the SPA, but any other route to the old page (licence banner, Profile page buttons, redirects after saving, bookmarks, the old top-bar menu, the old Profile / Change PIN pages) still opened the Razor screen. | `SpaRedirectFilter` (global MVC filter): a full-page **GET** of the old `Index` of any migrated controller, and of `Account/Profile`, `Account/ChangePin`, `Account/ChangePassword` (the PIN screen's old name), redirects to the React page, keeping the query string. POSTs, AJAX, details pages, exports and the old login are untouched. `?legacy=1` opens the old page anyway. Removed with the Razor pages at the cutover. No Razor view was edited. |
| 3 | Profile / Change PIN content should be centred | One column, left-aligned. | The page is a centred column (`--account-width`); header and card share the width. |
| 4 | Login: `/` shows the old design, `/app/login` the new one; keep the old | The React login had its own look. | `LoginPage` (+ css) now reproduces the Razor page: teal gradient, floating shapes, branding column with the three feature cards, English / العربية pills, translucent card with the coloured top edge, dark-initials user list, same texts. Mirrors in Arabic. The PIN pad is the shared `ui/PinPad`. |
| 5 | Hold cart: assign a customer | The hold dialog only had Notes; the customer could only be set at checkout. | The hold dialog has the same customer picker as checkout (search, balances, inline "New"). The held cart stores it; resuming brings it back. |
| 6 | An item with no stock should not block checkout | Checkout asked "Not enough stock… sell anyway?" (a prompt per sale). | Checkout always sends `allowInsufficientStock: true`; no prompt. The cart keeps its warning line (reworded: it can still be sold, stock stops at zero). |
| 7 | Added stock in Inventory, POS still showed none until Ctrl+F5 | The tiles shared the app-wide 30 s freshness: coming back to the till inside that window reused the old answer. (The server cache is cleared by stock adjustments; verified.) | The till's catalog queries (tiles, categories, search) are always re-asked on mount and on window focus; cached tiles stay on screen meanwhile. |

## Side effects handled
- `e2e/shell.spec.ts`: login now lands on the full-screen till (POS was flipped in P4), which has no rail; the helper steps onto `/app/orders` and waits for the shell before pressing keys.
- `e2e/notifications.spec.ts`: switches language the way the app does (storage **and** cookie).
- The cart Vitest seeds a session (the hold dialog's picker asks who may add customers).

## Tests
Vitest 576 (new: language cookie ×4, catalog freshness, hold with customer, sell-without-prompt), `dotnet test --filter Api.Infrastructure` 98 (new: redirect table ×8 + ×5, 6 live redirects, language cookie), `tsc`, `lint`, build (entry 153.9 KB gzip). Playwright against a clean demo DB: all specs pass except the three POS specs when run **after** `catalog.spec` in the same DB (the display-order spec reorders the tiles; they pass on their own and on a clean DB).

## Watch list
- The language cookie wins over `localStorage` at start-up. Anything that writes only `localStorage` (a test, a console) is overridden on the next load: go through `setLanguage` / `writeStoredLanguage`.
- Because of the redirects, the old Razor pages of migrated screens are reachable only with `?legacy=1`; the Definition-of-done line "old Razor page still works untouched" is therefore met only through that switch.
- Landing after sign-in is still the till (as the old app did).
