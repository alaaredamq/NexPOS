## For P2 (screen) — plug-in
Place `<CartPanel onCheckout={…} />` in the cart slot (needs `loadNamespaces('pos')` in the route loader; it needs a height from its parent and scrolls its own line list). Add products with `addToCart(product, { quantity })` (scanner `3*` prefix). `slots.ts` was not created by me: it is P2's.

## For P4 (checkout) — plug-in
- Enable the pay button on `useCartTotals().canCheckout` (= the server has priced exactly this cart; `false` while pending, refused or unreachable).
- Checkout body: `cart = totals.input` (or `buildCartInput(...)`), `totalAmount = totals.total` (only when `isServer`), `customerId = useCartStore.getState().customerId`. `totals.hasInsufficientStock` tells you in advance that `insufficient_stock` will be asked.
- After a successful sale call **`resetCart()`** (not `clear()`: `clear` is the cashier's undoable button; `resetCart` also empties the undo history so a sold cart cannot be undone back). On a failed sale touch nothing: the cart is plain state and survives.
- `setCustomerId(id)` is the hook for P4's customer picker; hold carries it. `heldCartId` says which held cart was resumed (see "odd").
- Both `Hold` and checkout use the **same** `PosCartInput`, so the server's refusal reasons (`price_below_minimum`, `product_not_found` …) surface in the same way.

## Decisions / deviations
1. **Prices are never stored as the browser's decision.** A line keeps *how* it is priced (`default` / `tier` id / `custom` amount + the currency it was typed in). Amounts are converted into the cart currency only when sent, so toggling the cart currency back and forth loses nothing.
2. **No per-line discount.** The API has a whole-cart discount only and the old till had no per-line one either; a "line discount" is the price picker (stored tier or custom price). The plan's "per-line and whole-cart discounts" is therefore met by price picker + cart discount.
3. **Weights are sent in the product's own unit** (the unit its price is per), not necessarily "kg/L" as the P1 DTO comment says. They agree for kg/litre products; for a product priced per gram, `weightOrVolume` is in grams, as in the old till. *(P1's XML comment could say "the product's unit".)*
4. **Unit aliases fixed:** the old converter treated `gram`/`litre`… as multiplier 1 (a "gram" product converted like kg). They are now aliases.
5. **Undo** = bring back what the last remove / clear / replace (resume) took away (10 deep). **Void last** (`removeLast`) = remove the most recently added line. Both exist in the store; the panel shows an Undo button only (no UI for void-last yet: P2's shortcuts can call `removeLast`).
6. **Stepper on weighed lines:** the old +/− on a weighed line changed `Quantity` without changing the price (a latent bug). Weighed lines now show an amount button that reopens the weight dialog; pieces get stepper + typeable number.
7. **Currency:** the cart prices in one currency (default; a button cycles through the active ones) and shows the total in the others as an estimate (`≈ LBP 2,864,000`). Totals the old till showed in LBP/USD side by side are covered by this.
8. **Money display:** whole amounts ≥ 1,000 drop `.00` (as `CartItem.formatMoney` did), everything else keeps two decimals. All digits are Latin.
9. **Tax:** a tax row is rendered only when the server's `taxAmount > 0` (today always 0, P1 decision 3).
10. **Resumed carts** are rebuilt from fresh product fetches (the held cart keeps no unit/stock/price list); lines whose product is gone are skipped with a warning toast. A held *amount* discount has no stored currency: it is read in the current cart currency. The held cart stays in the held list until deleted (as before).

## Dropped / not done (please read)
- **Manual item ("Add Manual Item")**: the old till pushed a negative-id line. `PosLineInput.productId` must be a real product and P1 gave it no API, so it is gone. If the shop needs it, P1 needs a "free-text line" endpoint first. **Decision for you.**
- **Pack without a linked single product**: the old till opened a "select a single product / create one" dialog. Now it shows a toast ("link one in Products") and adds nothing. Packs *with* `singleProductId` work (added as "Cola (from 6-pack)").
- The old `GetQtyInCart` quirk (counted lines + 1) is not carried over.
- Keyboard shortcuts / barcode focus handling belong to P2; the store/UI expose what they need.

## Odd / watch
- A held cart that was resumed and then **sold** stays in the held list (legacy behaviour, now visible as `heldCartId`). Deleting it after checkout would be an improvement; it is P4's call because it is a behaviour change. Likewise re-holding a resumed cart creates a second held cart.
- `usePricedCart` re-asks after 30 s stale on focus; a cart that has sat for minutes is re-priced when the cashier comes back, and `canCheckout` goes false until the answer arrives.
- The cart is in memory only (as before): a page reload empties it. Sign-out should call `resetCart()` (shell change, not mine).
- Network errors are retried twice by the app-wide query rule before the "cannot reach the server" notice shows (~3 s).
