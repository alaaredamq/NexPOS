## Deviations / dropped (and why)
- **Email receipt dropped.** The old `SendEmail` never sent anything (`ReceiptService.SendReceiptEmailAsync` is a `TODO` that only stamps `EmailSentAt`), yet both screens toasted "Receipt sent successfully". Not ported rather than pretend. The "Emailed" history line is not shown either (those rows are fake). Needs a real SMTP setting first → parking lot.
- **Printer diagnostics dropped from Orders:** `TestMarginAdjustments`, `TestFullWidthFormatting`, `PreviewThermalReceipt`, `TestFullReceiptFormat`, `TestSimplePrint`, `CompleteThermalDiagnostic`, `TestPrinterConnection`, `TestDirectPrint`, `TestPureTextPrint`, `PrintReceiptForCheckout`, `GenerateTextReceipt` (all `Settings.Manage`, development scaffolding, hard-coded printer name). **A2 (printers) should own a real "test print" if wanted.** They stay in the Razor controller until Cutover.
- **Dead / fake pieces not ported:** "Duplicate order" and "Add order note" (the old buttons only showed an alert), the status form's "additional notes" box (had no name, never posted), `CustomerOrders` / `ByDateRange` actions (no views exist; replaced by the list filters), `Orders/Receipt` + `ThermalReceipt` HTML pages (nothing linked to them; the receipt page + PDF replace them), `Receipts/generate-number`, the fake "+5.2 %" / "vs yesterday" trend chips and the receipts "Export" button (a placeholder toast).
- **"Recent" receipts tab folded into the list** (it was "valid receipts, newest first, max 50" = All, Valid filter, sorted by date). The Analytics tab is a view toggle on the same page; charts are plain bars/columns, no chart library (I1 picks one).
- **The date range now works.** On the old receipts page the date-range modal reloaded the table with `startDate/endDate` that the action ignored. Both lists now filter on `from`/`to` (local days).
- **No more 365-day / 1000-row cap.** The old orders list loaded the last year, the receipts list the latest 1000, each with the whole graph, on every click. The new queries read light rows (no cart items/products) for any range and sort/page on the server.
- **Money is never added across currencies.** The old tiles summed raw amounts and printed "$". Tiles now show one figure per currency (`$ 120.00 · L.L. 3,000,000.00`); the details page uses the order's currency everywhere (the old subtotal was hard-coded `$`).
- **Void now requires a reason on the server** (both old dialogs required it in JS only; an API call could void with none).
- **Receipt search also matches the phone** (the old "search receipts" box promised phone but did not search it); the receipts list sorts by void date on the Void filter.
- **A cancelled order shows no "Update status"** (it is final: cancelling again or reopening is refused with a code).
- **CSV hardening:** a customer name beginning `= + - @` is prefixed with `'` so Excel does not run it as a formula; UTF-8 BOM so Arabic names open correctly.
- Summary tiles keep the old "last 30 days"; revenue still excludes only Cancelled (Returned counts), as before.

## Things to know / decisions for you
1. **"Returned" is only a label.** Choosing Returned in the status form does not restore stock, void the receipt or touch debt/drawer (as before), and afterwards Cancel is refused (`order_closed`) because the order is no longer an "active sale" — so the stock can never be put back through the UI. I kept the behaviour, pinned it with a test, and the dialog now says so. **Decision for you:** should Returned reverse the sale like Cancelled (stock back, receipt voided)? Changing it is one line in `SaleReversalService` / `OrderService`, but it is a business rule, so I did not.
2. **A till sale is born "Delivered"** (status 3), not Pending — so the old "Pending orders" tile is normally 0. Unchanged.
3. **The POS checkout answer's `orderNumber` is `ORD-000441-20261101`** (with the local date); the Orders pages and the drawer use `ORD-000441`. The SPA's Orders pages use the short form; P4 may want to show whichever the receipt prints.
4. **Permissions as before, and a mismatch worth knowing:** the Cashier role has `Orders.View` (so sees Orders) but no `Sales.View` (no Receipts); Admin has both. `Receipts.View/Print` exist in the catalog but the old controller (and nav) use `Sales.View`, so I kept that.
5. Voiding a receipt and cancelling an order are the same reversal (`SaleReversalService`); doing one makes the other 409 (tested both ways).
6. Edits outside S1's folders (all additive except the test): the two repository methods, `SpaMigration.cs` (2 lines), `Tests/Api/Infrastructure/ApiConventionTests.cs` (the "not migrated" test used `Orders` as its example; it now picks whichever page is still waiting, so it will not break again as tracks land), `_shared/` helpers, locale JSON and the `Sales_*` resx keys. No frozen path (`app/api/core/ui/shell/styles`, `Program.cs`) touched, so no Core change-log line.
7. Service-side reading is in memory after a light SQL filter (date / status / customer): SQLite cannot ORDER BY a decimal and the search is "contains" on id / name / total, exactly like the old one. Fine for tens of thousands of rows; if a shop ever has far more, move the search into the repository.
