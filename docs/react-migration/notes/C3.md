## Endpoints
Inventory: `GET inventory` (page/pageSize/sort=`name|barcode|category|stock|minimum|maximum|cost|price|value|status`/dir/q) · `GET inventory/summary` · `POST inventory/{productId}/adjust {type: add|remove, quantity, reason}` · `PUT inventory/{productId}/minimum-stock {minimumStock}` · `GET inventory/reports/low-stock` (summary + paged items, q) · `GET inventory/reports/stock-value` (totals, two chart series, paged items, sort=`value|name|category|stock|cost`) · `POST inventory/reports/{low-stock|stock-value}/print` · `GET inventory/reports/{low-stock|stock-value}.pdf`.
Suppliers: `GET suppliers` (sort=`name|email|phone|balance|isActive|discount|products`) · `GET suppliers/summary` · `GET suppliers/options` (currencies) · `GET suppliers/{id}` · `POST/PUT/DELETE suppliers[/{id}]` · `GET|POST suppliers/{id}/debt-transactions` · `GET suppliers/export` (CSV).
Permissions copied from the Razor controllers: inventory list, reports, print, PDF = `Inventory.View`; adjust = `Inventory.Edit`; suppliers list/details/ledger/options/export = `Suppliers.View`; create = `.Create`; edit and debt entries = `.Edit`; delete = `.Delete`. Conflicts: 409 `supplier_has_balance`, 409 `supplier_in_use`.

## Decisions / differences from the Razor pages
1. **`SetMinimumStock` never existed on the old controller.** Both Razor views POST to `Inventory/SetMinimumStock`, which has no action (404 every time). The API implements it (`PUT inventory/{id}/minimum-stock`, `Inventory.Edit`) because the button is clearly meant to work.
2. **Adjust stock now records the reason.** The old form collected "Reason" and threw it away. It goes into a business audit row (`StockAdjusted`, details hold the type, quantity, before/after and reason). Quantity must be greater than zero: the old server accepted a negative "add", which silently removed stock. Decimals are accepted (kg, litres); the old input was integer-only in the browser.
3. **Dropped as stubs:** "View history" (toast "coming soon"), the inventory Export button (same), "Adjust critical stock" and the hidden reorder buttons on the low-stock report, and "Total value at risk" (hard-coded `$0.00`). The Excel / product-detail / adjust links on the stock-value table were also stubs; adjusting stock lives on the inventory and low-stock rows.
4. **Stock-value charts are ranked bar lists, no chart library.** The pie (categories, top 8) and bar (top 10 products) became horizontal bars with the same series; I1 picks the chart library and can swap them. No Chart.js.
5. **Create/edit of a supplier is a dialog**, like categories; details is a route. The old Create/Edit pages are not routes (`/app/suppliers/new` does not exist).
6. **Suppliers list:** the "Contact person" column (it just repeated the name) and the fourth tile ("Active contracts", a copy of Active) are gone; the tile is now "With balance". The product count per supplier is new on the details page (the old page showed it too).
7. **Debt ledger is paged** (20 a page) instead of "20 most recent of N". Entries entered here are `adjustment` (`ManualAdjustment`), as before; `purchase` / `payment` kinds exist in the enum but nothing creates them yet.
8. Money-ish rules unchanged: the balance is a running total moved by `ISupplierDebtService`; an edit never touches it; delete is refused while the balance is not zero, or while products (even deleted ones) or debt rows point at the supplier. Server messages for those come back localized (`Sup_*` resx keys).
9. Printing keeps the old shape: receipt paper or A4 PDF from one `PrintDocument` (D11). A printer that is missing answers 200 `printed:false` + message; the page shows it with "download PDF instead". The test host uses the demo no-op printer, so the tests only see `printed:true`.
10. Export of suppliers is a GET (the Razor one was a POST with an antiforgery token).
11. Stock figures: `Low` = a minimum is set and stock is at or below it; `Out` = stock <= 0 (an out-of-stock product with a minimum counts in both tiles, as before). Stock value is stock x cost (selling price when there is no cost) **in each product's own currency, summed without conversion** into the default currency's notation: the old figure, kept; mixed-currency shops get a wrong total (see watch list).

## Watch list (pre-existing, not changed here)
- **No default role holds `Suppliers.Delete`** (not even Admin), like `Categories.Delete`: the delete button is a 403 in both UIs until the Users page grants it. The API test grants it first.
- **The Manager role has `Suppliers.Manage` but none of View/Create/Edit**, and nothing checks `Manage`: a manager cannot open Suppliers. Probably wants adding to the defaults (owner's call).
- `Inventory.Adjust`, `Inventory.Reports` and `Inventory.Manage` exist but nothing checks them (Razor used View / Edit), so the API doesn't either.
- Stock value and the Inventory total add amounts in different currencies as if they were one.
- `StockAlertService` is not called after an adjustment or a minimum change (it never was); low-stock notifications still only arise after a sale.
- Stock changes are read-modify-write on the product row, like before: two simultaneous adjustments can lose one.
- `Product.UpdateAsync` is what writes the stock, so the audit interceptor also records a data-level `Update` of the product next to the `StockAdjusted` row.
- Playwright here needs `PW_CHROMIUM`; and Chromium refuses some ports (5061 is "unsafe"): use 5063 or 5057.
