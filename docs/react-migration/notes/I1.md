## Endpoints
`GET dashboard` (tiles, 10 latest orders, category split; cached 2 min under the **same keys** as the Razor page) · `GET dashboard/sales-trend?period=week|month|quarter|year` · `GET reports/summary` · `GET reports/sales?from&to` (local days, inclusive) · `GET reports/sales.csv?from&to` · `GET reports/sales.pdf?from&to`.
Permissions copied from the Razor controllers: dashboard = `Dashboard.View` (a **cashier holds it**), everything in reports = `Reports.View` (cashier does not; `Reports.Export` exists but the old controller never checked it, so nor does this). Range errors are 400 `validation_failed` on `to` (backwards, or over 3660 days).

## Decisions / differences from the Razor pages
1. **No chart library.** The plan recommended uPlot or recharts; the two charts needed (2-series line, donut) are ~250 lines of SVG in `_shared/charts/` and cost no bundle at all (entry still 148.6 KB gzip). They are LTR-forced (time and money read left to right in Arabic too), have a snapping crosshair + one tooltip, keyboard arrows, a legend, and a **table view** for the same numbers. The `dataviz` checks were run: the two series (brand teal + amber) pass CVD, normal-vision and contrast; the **teal fails the chroma floor** (it is the brand colour, and the category palette it comes from is muted on purpose) — mitigated by the dashed profit line, direct legend and the table.
2. **The old Reports index/pop-ups collapse into one page.** Daily / monthly / yearly reports, top products, category analysis and sales trend were all the same report with another range; the page is a date range (URL-mirrored, presets + "This year"). Dropped: the three "include …" checkboxes (always included), the "Payment methods — coming soon" stub, the per-report modals.
3. **Export now exists.** The old Export only answered "will be implemented". CSV (UTF-8 BOM, cells starting `= + - @` defused, tested) and an A4 PDF through the same `PrintDocument` path as the inventory reports (D11). The PDF is audited (`PdfGenerated`); no receipt-printer button (nothing asked for it).
4. **Bug fixed in `SalesReportService` (money report):** `GetAllAsync(c => …)` loaded the carts **without their lines**, so items sold, top products and category sales were always 0 / empty on the old page. They are now loaded with product + category. Revenue per line uses `CartItem.TotalPrice` (weight × price for weighed products) instead of `UnitPrice × Quantity` (which counted a 0.5 kg line as 1 piece).
5. **Payment-method split is real.** The old service returned "100% Cash" for everything. It now groups the receipts of the range (void receipts excluded). Percentages are of the listed methods.
6. **Dashboard figures:** unchanged computation (same `DashboardService`, same 2-min cache keys). Two dropped: the fake "% vs last month" on customers and products (the service always returned 0) — they are plain counts now; the hard-coded sample legend of the donut. The recent-orders status used to be painted "Completed" on every row; it is now the order's real status (a cancelled sale shows Cancelled). Payment method column added (already in the payload). Status `Cancelled` rows are still listed, as before.
7. **Donut hues collide.** `CategoryPalette` has 7 hues for up to 10 categories (same function the POS tiles use — one source, `_shared/categoryPalette.ts`), so two slices can share a colour. Identity therefore never relies on colour: the legend names every slice with share and amount, and hover highlights the slice. If it bothers, the fix is a ranked bar list instead of a donut (the `dataviz` skill prefers it) — a design call, not done.
8. **Quiet days are filled in.** The server sends only buckets that have sales; the chart fills the rest with zero (`dashboard/trend.ts`, unit-tested) so a slump is not smoothed into a line. Reports does the same on the server (every day of the range is listed).
9. **Top products rank by quantity, the dashboard's by revenue** — each page keeps its old rule. The dashboard's top-products / top-customers / inventory-status endpoints (never shown on any page) are not ported.
10. Dates: ranges are **local days** converted to UTC at the edge (`AppTime`), as before. The dashboard sends bucket dates as `yyyy-MM-dd`; labels are formatted in the browser in the UI language with Latin digits.
11. Currency: every amount is in the **default currency** and shown with its notation (orders in another currency are summed as stored, exactly as the old page did — converting is a money-rule change).

## Watch list (pre-existing, not changed here)
- **`CacheService.Clear()` only drops entries stored by the same scoped instance** (its reset token is per instance), so a `Clear()` from one request does not evict what another request cached. Dashboard figures therefore stay stale up to 2 minutes after a sale, as on the Razor page. The tests evict by key instead.
- The dashboard's "profit" counts only lines whose product has a cost price (as before); lines without one contribute 0.
- `ReportService` (`IReportService`, 16 `object`-returning methods) is not used by any controller; left for Cutover to delete. `IExportService.ExportToExcelAsync` still returns CSV.
- Reports build the order graph in memory for the range (cap 3660 days). Fine for a shop; move to SQL grouping if a store has years of busy days.

## Not done / not verified
- Licence-stopped and idle-timeout behaviour are inherited from the shell: neither page is a sales route, so a stopped licence leaves them open (as the Razor ones were).
- Audit: requests are audited by `AuditRequestMiddleware` as `GET Api.Dashboard/…` / `Api.Reports/…`; only the PDF writes an explicit business entry. The Razor controllers wrote none.
- The PDF was checked as a file (`%PDF` header), not opened in a viewer; the demo host has no real printer (and no print button here).
- The demo database only has sales on the day it was seeded, so the month chart there is a single point; the multi-point month / quarter / year shapes are covered by unit tests and the reports page (30 days of seeded history), not by eye on the dashboard.
