## For module tracks — how to plug in
- **Routes:** `modules/<name>/routes.tsx` default-exports `RouteObject[]` with paths **relative to `/app`** (`{ path: 'orders', lazy: ... }`). `session.nav[].spaPath` tells you the path your page must use.
- **Full-screen pages (POS):** put `handle: { layout: 'bare' }` on the route. It renders behind the sign-in but **without** rail/top bar; render `<LicenseBanner floating />` yourself. Idle lock still applies.
- **Guards:** wrap with `{ element: <RequirePermission permission={Permissions.Orders_View} />, children: [...] }`; selling routes also `<RequireSalesLicense />`. Inside components `const can = useCan(Permissions.X)`. These are UX only; the API's `[RequirePermission]` is the real check.
- **Session data:** `useSession()` (user, role, permissions, nav, license, branding, drawer, unreadNotifications). It refreshes every 60 s, on window focus, and after `license_sales_stopped` / `unauthenticated` / `forbidden` API errors, so don't poll for those yourself.
- **Flip the page on:** the one line in `Web/Helpers/SpaMigration.cs`. Until then the rail entry is a plain anchor to the Razor page and `/app/<page>` shows the placeholder (which links to the Razor page).
- **Namespaces:** shell strings are `Shell_*` keys in the `common` namespace (hand-added, survive `npm run i18n:export`). Rail/section labels come from the server already localized.

## Decisions / things that behave differently from what you might expect
- **Idle timeout is new behaviour.** The Razor app had no client lock (cookie lives 8 h, sliding). 30 min mirrors the server's `AddSession` idle limit. It *signs out* (server cookie cleared) rather than showing a PIN-only lock, because a client-only lock would leave a live 8 h cookie behind it. The login page then opens straight on the last user's PIN pad. To change the limit edit `IDLE_TIMEOUT_MS`. If the POS should be exempt (cashier standing at the till), do it in P2 — scanner input counts as activity already.
- **Notification bell is a link + badge**, not a dropdown. There is no `api/v1/notifications` yet (track I2). The count rides on the session refresh.
- **Drawer chip reads `session.drawer`** (refreshed every 60 s + on focus). S2 can swap in `useDrawerStatus()` with a dedicated endpoint; the chip only needs `{isOpen, openingCash}`. Shown only when the session says the user can use a drawer (`Sales.View`).
- **Landing page = POS** for roles that have it (the Razor home), else the first nav entry. Unmigrated pages open the placeholder in the SPA rather than bouncing to Razor, so the shell stays testable.
- **Language:** first visit adopts `session.language`; a stored `nexpos.lang` always wins. Switching re-fetches the session because nav labels are localized server-side.
- **Profile / Change PIN** in the user menu are links to the Razor pages (A1 replaces them). `mustChangePin` also goes to the Razor page.
- `core/auth` imports two small things from `shell/` (`StatusCard`, `legacyAccountPath`) — both are 0D's; harmless, but don't copy the pattern into modules.
- Playwright config got an optional `PW_CHROMIUM` env override (reuse an installed Chromium instead of downloading the version this Playwright wants).
