# P1 — POS API + contract: handoff notes

**Branch:** `react/P1` (from `react/main`). **Status:** ◑ in review. Read `Web/Api/README.md` first for the conventions; the DTOs are in
`Web/Api/Pos/Contracts/PosDtos.cs` and `Web/Api/Carts/Contracts/CartDtos.cs` (XML comments become the TypeScript docs in `client/src/api/schema.d.ts`).

## What exists
| Route | What |
|---|---|
| `GET pos/categories`, `GET pos/products` (`categoryId`, `mainScreen`, `q`, `page`, `pageSize`) | tile data; `mainScreen=true` = display order, falling back to all active products (`isMainScreen` says which) |
| `GET pos/products/search?q&barcodeOnly&skip` | exact barcode first, else 20 name matches per page (`hasMore`); scanner miss (`barcodeOnly`) = 404 `product_not_found` |
| `GET pos/products/{id}`, `GET pos/products/{id}/prices?currencyId` | one product; price choices + minimum custom price in that currency |
| `POST pos/price` | **the server's price of a cart** (rules below) |
| `GET pos/currencies`, `payment-methods`, `discounts`, `drawer`; `GET/POST pos/customers` | reference lists, lazy customer picker (`hasMore`, no total), quick-add |
| `POST pos/sales/checkout` | the sale (idempotent) |
| `GET pos/sales/recent`, `POST pos/sales/{orderId}/print`, `GET pos/sales/{orderId}/receipt.pdf` | last sales, reprint, PDF |
| `GET/POST/DELETE api/v1/carts`, `GET/DELETE carts/{id}` | held carts (park, list, resume data, delete one / all) |

`ReceiptDto` (S1 soft dependency): there is no separate receipt DTO. `PosSaleDto` (the checkout response) carries everything a success screen / on-screen receipt needs
(lines, subtotal, discount, tax, total, paid, change, payment method, customer, `receiptId`/`receiptNumber`); paper and PDF stay server-side (D11). S1 can add a
full receipt-detail DTO when it builds the receipts page.

## Rules the UI must follow
- **Cart in, never prices.** A line is `{productId, quantity, weightOrVolume?, priceTierId? | customPrice?}`; `customPrice` is in the cart currency. One line per product (a repeat is 400 `duplicate_product`).
- **Weight/volume:** send `weightOrVolume` in the product's **base unit** (kg / L); `quantity` stays 1. Unit conversion (300 g → 0.3 kg) remains client-side (P3). `unitKind` on the product says which products need it (same unit lists as `UnitConverter.js`).
- **Display = server.** Call `pos/price` (debounced) on every cart change; show its numbers; send its `total` as `totalAmount` at checkout. The cashier may lower it (becomes a discount on the receipt) or nudge it for cash rounding; more than max(1.00, 2 %) away is 409 `total_mismatch`.
- **Rounding** (golden file `docs/react-migration/golden/pos-pricing.json`, run by `Tests/Api/Pos/PosPricingGoldenTests.cs`; **P3's Vitest must read the same file**): a unit price converted into another currency = `amount / fromRate * toRate`, `Math.Round(x, 2)` = **banker's rounding**; same currency untouched; line total = unit × (weightOrVolume or quantity), not rounded; `total` = subtotal − discount rounded to 2 dp. JS has no banker's `toFixed`; implement it.
- **Idempotency:** a fresh `idempotencyKey` per attempt; after a lost response retry with the **same** key and the first sale comes back (`replayed: true`). A refused attempt does not burn the key (fix the cart / confirm "sell anyway" and resend). Same key + different cart = 409 `idempotency_key_reused`. Kept in memory for 30 min like the legacy guard: an app restart forgets it.
- **Branch on `code`**, not text: `insufficient_stock` (offer "sell anyway": resend with `allowInsufficientStock: true`), `total_mismatch`, `drawer_not_open`, `customer_not_found`, `debt_requires_customer`, `payment_method_invalid`, `price_below_minimum`, `price_not_available`, `invalid_discount`, `duplicate_product`, `invalid_amount`, `currency_not_found`, `product_not_found`, `cart_not_found`, `order_not_found`, `checkout_failed` (any other rule of the checkout service; `detail` says which), plus `license_sales_stopped` (403, checkout and park only).

## Decisions / deviations (please read)
1. **Mixed-currency carts now work; they did not before.** The old checkout cart stored each line in its product's currency and `POSCheckoutService` summed them raw, while the browser showed converted prices, so a cart in LBP with a USD product failed the total check. The API stores lines of a foreign-currency product at the converted price the cashier saw (only those lines; `POSCheckoutService` is untouched). Single-currency carts behave exactly as before. Tested for EUR and LBP.
2. **A closed drawer does not refuse a sale by default** (the old till sold anyway; the sale just was not part of any Z report). `requireOpenDrawer: true` makes it 409 `drawer_not_open`; `GET pos/drawer` feeds the prompt. **Decision for you:** should P4 turn this on? It changes behaviour, so I left the default alone.
3. **Taxes are not applied at the till** (known unknown #4): `POSCheckoutService` hard-codes `taxAmount = 0` and the receipt carries 0. `PosPricedCartDto.TaxAmount` is always 0 so the shape survives if that changes. Which of the two `TaxService`s survives is A3's call.
4. **Permissions = parity with the old `POSController`:** every till endpoint is `[AnySignedInUser]` (the old actions only had `[Authorize]`), except quick-add customer (`Customers.Create`) and last-sales / reprint / PDF (`Orders.View`, as `OrdersController`). Checkout and parking add `[RequireSalesLicense]`. So a user without POS access can sell through the API exactly as they could through `/POS/Checkout`: a hardening candidate (`POS.Manage`) for you to decide, not changed here.
5. **Held carts keep the legacy storage** (`Cart.DiscountCode` doubles as the note field, `__WALKIN__` marker) so the Razor till and the SPA can resume each other's carts during the strangler period. On resume the discount label and notes are one string (`notes`); `discountLabel` is null. Held carts record no currency: resumed lines carry the product's currency and unit price (`priceKind`: default / tier / custom); re-price through `pos/price`.
6. **A refused sale leaves nothing behind:** the cart built for it is soft-deleted (the old flow left orphans). The parked-cart list still hides only carts with an order in the last 30 days (legacy rule; carts of old sales made by the *old* till can reappear after 30 days. Pre-existing, not fixed).
7. Customer search returns `hasMore` instead of `total` (the service has no count): a documented deviation from the list wire format. `GET pos/products` accepts only `sort=name`.
8. The purchase price is never in a product tile (the old `CheckPrice` returned it to every cashier). `minPrice` of a price-options call is the purchase price by definition (unchanged from the old `GetPriceOptions`).
9. Dropped (no API): `RefreshCache`/`ClearCache`/`GetCacheStats` (internal; checkout already clears the POS caches), `GetCustomers` (all customers; replaced by the paged search), the Select2/autocomplete product endpoints (use search), `PrintReceiptToUsb` (raw HTML to a printer, unused by POS.js; reprint goes through the thermal service), `CartsController`'s item-by-item endpoints (the SPA keeps its cart in memory and sends it whole), `ValidateCart`/`CalculateTotal` (replaced by `pos/price`).
10. Audit: checkout still writes `SaleCompleted`/`SaleFailed` through the unchanged service; reprint writes `Print`/`PrintFailed`, the PDF `PdfGenerated` (same as the Razor actions). Requests appear as `POST Api.PosSales/Checkout` etc.
11. Messages: new `Pos_*` keys in `SharedResource.{en,ar}.resx` (EN + AR). Texts of exceptions from lower services (a `checkout_failed` detail) are still English.

## Tests (D10)
`Tests/Api/Pos/`: 72 tests; whole suite 488 green. Catalog / search / price / lookups (`PosCatalogAndPricingTests`), checkout + held carts + drawer + debt + currencies + idempotency + licence (`PosCheckoutTests`), golden arithmetic (`PosPricingGoldenTests`). `PosTestKit.Selling` is the same app with a licence that allows selling; the shared host has none.
Not covered: a *failing* printer (the test host uses the no-op `DemoPrinterTransport`); a role without `Customers.Create` / `Orders.View` (the demo users are Admin and Cashier, which have both); two different carts racing for the last unit (the atomic stock deduction is the existing service's).

1. `cd client && npm run api:types -- --no-build` after a Web build gives no diff (`schema.d.ts` is committed).
2. Run the app (Development), sign in, open `/swagger`: tags `pos` and `carts`. Try `POST /api/v1/pos/price` with a USD product in an LBP cart.
3. Park a cart in the Razor till, then `GET /api/v1/carts` shows it.
4. Sell once through `pos/sales/checkout` against the demo DB (not `nexpos.db`) with a real receipt printer attached; check the slip and the Z-report line.
