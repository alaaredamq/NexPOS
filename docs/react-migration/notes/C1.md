Endpoints (old action → new): `GetProducts` → `GET products` (+`summary`); `Create`/`Edit`/`Delete`/`Details` → `POST`/`PUT`/`DELETE`/`GET products[/{id}]`; `GenerateBarcode` → `GET generate-barcode`; `StickerSettings`/`StickerPdf` → `GET sticker-settings` / `POST sticker-pdf`; `ExportProducts`/`ImportTemplate`/`ImportProducts` → `GET export` / `GET import-template` / `POST import` (multipart, `apply=false` is the preview). New: `GET lookups` (form + filter choices), `GET options` (pack's single-product picker, replaces `/POS/SearchProductsForSelect2`).

Permissions per action are the old ones: everything `Products.View`; create/generate-barcode `Products.Create` (generate also accepts `Products.Edit`, because the edit form has the button); edit `Products.Edit`; delete `Products.Delete`; import needs `Products.Create` **and** `Products.Edit`.

## Deviations / dropped (and why)
- **Product images: nothing to port.** The plan expected image upload/serve; the old forms never had an image field (`Product.Image` exists, nothing reads or writes it; `ImageUrl` on the old DTOs is dead). Not added (no new features).
- **Import is CSV only**, as before. The plan said "CSV/XLSX"; `ProductImportExportService` has no XLSX. Parking lot.
- **Brand box dropped.** The old form had a Brand text field that was never saved (every product gets `BrandId = 1`). Removing a field that did nothing.
- **Low-stock rule kept as the old list's literal: above 0 and at most 5 units**, now decided by the server (`StockLevel`, `lowStockThreshold`) so the list, tiles and filter agree. The details page used `MinimumStock` for its badge; the new one uses the same server rule as the list (one rule instead of two). Say so if you want `MinimumStock` to drive it.
- **Pack products:** the old API accepted a pack without size/single product even though the form marked both required; the API now requires both (create only). Pack fields are create-only, as before; the edit page shows the pack read-only.
- **"Add product" pop-up** (`?noSidebar=true` window that closed itself) is now a plain link that opens `/app/products/new` in a new tab; no auto-close.
- **ID column dropped** from the list (the old one was the DB id).
- **Barcode required on edit too** (old edit DTO allowed null; the column is NOT NULL, so a blank would have crashed).
- The old delete/details/edit pages were not localized (hard-coded English); the SPA versions are, with new AR text — review the Arabic wording.
- **Details "View inventory" link** uses the Inventory nav entry's `href` from the session, so it follows the Razor page until C3 migrates it.

## Things to know
- **The seeded `Admin` role has no `Products.Delete`** (only SuperAdmin does) — same in the Razor app, where the delete button showed and then 403'd. The SPA hides the button without the permission. Not changed (A1 owns roles).
- Money in the form is entered in the product's currency; the profit preview is display only. Nothing is totalled in the browser.
- Label printing path is unchanged (D11): desktop → `electron.printSticker` with the HTML label; browser → bars encoded with JsBarcode (lazy chunk, 11 KB gz) and the server draws the PDF. Printer + "show price" use the same `localStorage` keys as the Razor pages.
- `form.ts` has a small `zodResolver` (no `@hookform/resolvers` in the project). Promote to `ui/` at cutover when a second module needs it.
- Core change (frozen path): `client/src/api/http.ts` now sends a `FormData` as multipart and has `http.download` / `http.downloadPost` (blob + `Content-Disposition` file name). Additive; tests in `api/http.test.ts`. Other tracks with exports/uploads can use it.
- Generated `schema.d.ts` only contains DTOs referenced by `[ProducesResponseType<T>]`: add one for every action that returns a bare type (the list returns `ProductListItemDtoPagedResult`).
